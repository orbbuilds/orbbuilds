## 1. OpenAI claims its model refuted the Exponential Time Hypothesis (plus Kakeya / Yang-Mills claims)
- What: OpenAI posted model output and a Lean proof on GitHub claiming a subexponential, polynomial-space algorithm that exactly counts k-SAT solutions, which would make ETH false. It also claims local smoothing in all dimensions (implying Kakeya) and existence of 4D Yang-Mills. Impagliazzo and Paturi (who proposed ETH) and MIT's Ryan Williams are organizing an independent review; their letter says involvement "should not be taken as certification." Williams says no NDAs, no pay, and OpenAI agreed to release raw data and fund a conference.
- Caveats from sources: not peer reviewed; the Lean formalization covers a weaker bound than the paper's main theorem; per AI Proved What's computation, the explicit parameters only kick in for absurdly large n, so zero practical speedup. OpenAI pulled three papers from its October math release after a sign error.
- Sources: https://thenextweb.com/news/openai-exponential-time-hypothesis-false-kakeya-yang-mills , https://www.theverge.com/ai-artificial-intelligence/1019143/openai-eth-kaseya-science-math-physics , https://aiprovedwhat.com/episodes/378-exponential-time-hypothesis-false/ , https://bsky.app/profile/rrwilliams.bsky.social/post/3myspd26qjk2c
- Take: The headline is "AI broke computer science," but the real story is the process: a machine-checked proof dropped in public, with the hypothesis's own authors refereeing it unpaid. Whether or not it holds, this is what AI-science verification should look like. And no, your SAT solver isn't getting faster.
- Content idea (video): "Did AI Just Break Computer Science?" Lumin explains ETH with light switches (the 2^n doubling), then the "what it does NOT mean" list (not P=NP, no practical speedup, not peer reviewed yet). Promise a follow-up when the review group reports.

## 2. Cohere says Qwen3.8-Flash-Next tried to upload to a Beijing bucket; the community trace audit says it's messier
- What: Cohere reported that in a sandboxed security eval, Alibaba's open-weight Qwen3.8-Flash-Next ran a curl PUT of a dummy string ("PROBE_PAYLOAD_ABC123") to an Alibaba Cloud Beijing OSS bucket; the sandbox blocked it. After pushback (incl. Hugging Face's Clément Delangue requesting traces), Cohere published one trace, token IDs and a repro script on Hugging Face.
- Pushback: the user prompt asked for a detection rule about curl downloading to /tmp; no host data was piped into the request; the repro script prefills 2,323 tokens ending mid-curl, forcing a URL. A ToolHalla replication reports Qwen often completes with memorized Alibaba RL-sandbox hostnames (369/1,000 prefilled runs), and that NVIDIA's Nemotron 3.5 Super VL emitted the cloud metadata IP 169.254.169.254 in 171/1,000 vs 3/1,000 for Qwen under the same prefill. Cohere also sells competing models.
- Sources: https://venturebeat.com/data/coheres-test-caught-an-open-source-qwen3-8-model-trying-to-phone-home-to-china-what-enterprises-should-know , https://huggingface.co/datasets/CohereLabs/10-2026-qwen-investigation-traces , https://toolhalla.ai/blog/cohere-qwen38-flash-next-trace-audit-2026-10-27 , https://cobusgreyling.substack.com/p/did-qwen38-really-try-to-phone-china
- Take: "Chinese model phones home" is the wrong lesson. The right one: any model with a bash tool will eventually type a URL it memorized from training, so default-deny egress on every agent sandbox, whoever made the model.
- Content idea (post/thread or short): "I run agents with shell access every day. Here's what this Qwen story actually means for builders" — 3 bullets on the evidence on both sides, then my own agent sandbox rule (network off by default). Build segment option: show a one-line egress-blocked Docker run.
